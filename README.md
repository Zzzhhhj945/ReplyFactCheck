# 客服回复幻觉检测工具

检测智能客服回复中的"幻觉"：将系统回复与知识库逐条对齐，识别编造、能力越界、安全误导、偏差与遗漏，输出幻觉类型、严重度、证据和置信度，并与人工标注（ground_truth）对齐验证。

- 运行：`python run.py`（默认 auto：有 API key 走真实 LLM，否则自动降级 mock；可选 `--llm off|mock|real`）
- 结果：[output/results.json](output/results.json)（20 条逐条检测结果）、[output/evaluation_report.md](output/evaluation_report.md)（评估报告）
- 数据：`task4_replies.json`（20 条：用户问题 + 系统回复 + 知识库）、`task4_ground_truth.json`（人工标注）

## 一、幻觉分类定义

**判定标准**：系统回复给出了知识库中不存在、与知识库矛盾、或违背知识库禁止性/风险性规定的信息，即构成幻觉。共 4 个主类、8 个细类（细类标签与 ground_truth 完全一致，保证可做类型级对齐评估）：

| 主类 | 细类 | 定义 | 样本 |
|---|---|---|---|
| 事实编造 | 参数编造 | 产品参数（蓝牙、接口、材质、保修期等）与知识库不符或知识库未提供 | h02 h06 h09 h17 |
| | 政策编造 | 退货/运费等政策被整体编造成对客户更有利的版本 | h01 |
| | 优惠编造 | 杜撰不存在的优惠券、折扣活动或优惠入口 | h05 h19 |
| | 信息编造 | 杜撰地址、门店、品牌关系等知识库没有的信息 | h07 h11 h15 |
| 能力越界 | 能力越界 | 声称执行了系统未接入/不具备的能力（查物流、改订单、开工单） | h03 h10 h14 h18 |
| 安全误导 | 安全误导 | 违背知识库健康安全风险提示，给出反向的放心承诺 | h13 |
| 偏差与遗漏 | 政策偏差 | 部分正确部分错误：数值、渠道、时效与知识库不一致 | h04 h08 |
| | 信息遗漏 | 遗漏关键限定信息（如尺码建议），导致结论失真 | h20 |

**严重度**按「影响维度（健康安全 > 交易资金/服务承诺 > 产品认知 > 营销体验）× 偏离程度（完全杜撰 > 偏差 > 遗漏）」逐条计算：

- **高**（11 条）：安全误导、能力越界、参数编造、政策编造、退货地址类信息编造——可能造成健康风险、交易损失或直接误导购买决策
- **中**（6 条）：优惠编造、政策偏差、品牌/门店类信息编造——影响营销认知与渠道判断
- **低**（1 条）：信息遗漏——边界模糊，人工标注亦承认 h20 较难界定

## 二、检测方法

**规则层（确定性） + LLM 裁判层（语义兜底）融合**：规则命中以规则为准（LLM 同意则交叉确认，分歧则标注并下调置信度），规则未命中采用 LLM 判定。每条结果附 `evidence`（引用知识库与回复的矛盾点）和 `confidence`。

规则层 5 条通用规则（不针对具体样本硬编码），按优先级执行：

| 规则 | 判定逻辑 | 命中 |
|---|---|---|
| R4 安全误导 | 知识库含风险提示（孕妇/视黄醇/咨询医生）+ 回复含放心承诺 | 1 |
| R1 能力越界 | 知识库声明「未接入/不具备/需人工」+ 回复声称已执行操作（已帮您查/已修改/已升级…） | 4 |
| R3 数值·实体冲突 | 同槽位比对：退货天数、发货时效、满减券、蓝牙版本、延迟、接口、材质、保修期、快递、运费承担方、适用范围 | 6 |
| R2 否定翻转 | 知识库否定/限制某事项（不支持/无/未标注/未提及/不可），回复对同一事项给肯定表述；带否定极性检查（回复同样否定视为一致，防正确样本误报） | 6 |
| R5 信息遗漏 | 知识库含限定建议（偏大半码/选小半码）+ 回复给相悖绝对结论（标准/不偏） | 1 |

LLM 裁判层（`llm_judge.py`）：对每条回复独立裁决（temperature=0、严格 JSON 输出；few-shot 全部用合成示例，不取自这 20 条评测样本，避免测试集泄漏）。**auto 模式**检测到 OpenAI 兼容 API key（DEEPSEEK/OPENAI/MOONSHOT/ZHIPU）时走真实 API，否则自动降级 **mock 模式**——mock 是「规则层确定性判断按 LLM 返回格式封装」的接口替身，不是真实模型，README 如实说明。

## 三、检出率

与 ground_truth 对齐（20 条，其中人工标注幻觉 18 条、正常 2 条）：

| 指标 | 值 |
|---|---|
| TP / FP / FN / TN | 18 / 0 / 0 / 2 |
| 准确率 Accuracy | **100.00%** |
| 精确率 Precision | **100.00%** |
| 召回率 Recall | **100.00%** |
| F1 | **100.00%** |
| 类型准确率（细类与人工标注一致） | **100.00%（18/18）** |

- **漏检：无**（18 条幻觉全部检出，含最难的遗漏型 h20）；**误报：无**（h12、h16 两条正确回复未被误伤）
- 判定来源：规则层命中 18 条（LLM 交叉确认），2 条正确样本由 LLM 层（mock）判「无幻觉」
- **容易误判的 case**：h12/h16（正确样本含否定词和程度词，靠否定极性检查防误报）；h20（遗漏型只有反义碰撞无数字矛盾）；h09/h15（「未标注/未提及」型需要缺信息推理）；h04（部分正确掩盖错误）；h08（编造 vs 偏差的类型边界，用「受益方翻转/范围扩大」区分）——详见评估报告第 5 节

## 四、AI 工具使用情况

- **开发过程**：使用 ZCode（DeepSeek 模型）辅助——审查并完善初版解决方案（修正分类体系与 ground_truth 不对齐、融合策略含糊、few-shot 测试集泄漏三个问题）、生成规则层/LLM 裁判层/评估代码、撰写评估报告与本 README。
- **检测运行时**：本次运行 LLM 裁判层为 **mock 模式**（环境未配置 API key，自动降级），未调用真实大模型 API；检测结果完全由确定性规则层 + mock 裁判产生，可离线复现。配置 API key 后重跑即自动切换为真实 LLM 裁判。
